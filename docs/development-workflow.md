# 開発ワークフロー

1. GitHub Issue を読み、対象範囲・対象外・完了条件を確認する。
2. 関連ドキュメントと現在の実装を確認し、必要最小限の変更を設計する。
3. 作業ブランチで実装し、対象の振る舞いをテストに追加または更新する。
4. `pytest`、`ruff check .`、必要に応じて CLI の手動確認を実行する。
5. 変更内容、設計判断、検証結果、未解決事項、完了条件への対応を報告する。

## 変更時のルール

- `main` へ直接変更・push しない。
- コミット、push、Pull Request 作成は明示的な依頼がある場合だけ行う。
- Issue の対象外を先取りしない。
- 外部操作や破壊的操作には、人間の承認が必要であることを設計上明示する。
