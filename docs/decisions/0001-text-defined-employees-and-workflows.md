# ADR 0001: 社員とワークフローをテキスト定義する

## 状況

業務ごとにコードを変更せず、担当する AI と工程を人間が確認・変更できる必要がある。

## 決定

社員とワークフローは YAML または Markdown で定義し、アプリケーションは Pydantic モデルで読み込み・検証する。定義の読み込み、一覧表示、事前検証は次の Phase で実装する。

## 根拠

- Git でレビュー・履歴管理しやすい。
- 人間が工程順序と担当範囲を明示できる。
- 実行前の静的検証に適している。

## 影響

実行エンジンは定義を補完せず、検証済みの定義だけを受け取る。実行時には使用した定義のスナップショットを保存する。
